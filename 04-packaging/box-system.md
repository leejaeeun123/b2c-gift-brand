# 박스 시스템

> 2026-08-30 · 재은 결정 — **무지 크라프트 박스를 쓰지 않는다. 기성 화이트 박스에 1도 블랙으로 직접 디자인한다.**
> 사양·문안 세부는 디자인 단계에서 이 문서에 이어 적는다.

---

## 0. 이 결정이 바꾸는 것

`§2.1 상품화 모델`에서 우리 상품의 실체는 **조합·포장·문장** 셋이라고 정리했습니다.
박스를 디자인한다는 건 그 셋 중 하나를 **가장 큰 면적에 올린다**는 뜻입니다.

소로이샵을 포함해 대부분의 그릇 편집숍은 무지 크라프트를 씁니다. 이유는 하나예요 — **싸고 MOQ가 없어서**입니다.
디자인 박스로 가면 그 자리에서 갈라지는 대신, **비용과 재고가 따라옵니다.** 아래는 그 대가를 다루는 문서입니다.

---

## 1. 사양 확정 (2026-08-30)

| 항목 | 결정 |
|---|---|
| 규격 | **한 사이즈.** 규격이 늘수록 재고·발주가 배로 는다 |
| 원지 | **기성 화이트 박스** |
| 인쇄 | **1도 블랙** |
| 디자인 | **1~2종** |

> 상품과 제작 견적에 따라 달라질 수 있는 잠정 사양입니다. 다만 아래 세 가지는 이 결정에서 곧바로 따라옵니다.

### 1-1. 목형비가 사라진다

기성 규격을 쓰면 **칼선(목형)을 새로 뜨지 않습니다.** 자체 제작 박스에서 가장 큰 초기비가 통째로 빠집니다.
남는 비용은 셋뿐입니다 — **인쇄판비 · 개당 단가 · MOQ**.

### 1-2. 화이트 + 블랙 1도는 우리 비주얼과 정합한다

손그림 선화는 애초에 <b>단색</b>입니다. 풀컬러가 필요 없습니다.
흰 원지에 검정 잉크면 `color-palette.md`의 잉크 단색 원칙(포인트 컬러 없음)과 그대로 맞습니다.

> **흰 박스는 오염과 찍힘이 잘 보입니다.** 이 약점은 이미 해결돼 있습니다 —
> **겉 택배 상자를 따로 씌우기로 했으니**(§4-1) 흰 박스는 운송을 겪지 않습니다.
> 두 결정이 서로를 받쳐 줍니다.

### 1-3. ⚠️ 한 사이즈의 대가 — 세트가 박스에 맞춰진다

이게 가장 중요한 지점입니다. **박스가 하나면 세트 구성의 상한과 하한이 박스로 정해집니다.**

| 문제 | 대응 |
|---|---|
| 큰 세트가 안 들어간다 | **박스에 안 들어가는 세트는 만들지 않는다.** 상한을 상품 기획 규칙으로 못 박는다 |
| 작은 세트가 헐렁해 보인다 | 습자지 완충으로 채운다 · 소품을 하나 더 넣어 구성을 맞춘다 · 또는 **소형은 박스 없이 띠지+파우치**로 별도 라인 |

**그래서 사이즈는 주력 세트(M급, 4~6점)를 기준으로 잡습니다.** 가장 많이 팔릴 구성이 가장 잘 담겨야 합니다.

**정하는 방법** — 숫자를 추정하지 않습니다. 도매 상가에서 **실제로 살 접시·볼의 지름과 높이를 재고**,
주력 세트를 실물로 한 번 담아 본 뒤 기성 규격표에서 고릅니다.

- [ ] 주력 세트 구성품 실측(지름·높이·개수)
- [ ] 포갰을 때 총 높이 + 완충 두께
- [ ] 기성 규격 후보 2~3개 비교
- [ ] **가장 큰 세트와 가장 작은 세트를 같은 박스에 담아 보기**

### 1-4. 디자인 1~2종을 어떻게 나눌까

**박스는 1종으로 고정하고 변주는 띠지로 주는 쪽을 권합니다.**
`§3`에서 이미 정한 원칙과 같습니다 — **자주 바뀌는 정보는 자주 찍는 것에 올린다.**
상황(새 식탁·둘이 쓰는 상)은 늘어나고 바뀌는데, 박스는 한 번에 많이 찍어 오래 씁니다.

2종을 쓴다면 형태가 아니라 **인쇄 밀도**로 나눕니다.

| | 쓰는 자리 |
|---|---|
| **A 여백형** — 워드마크 + 모티프 하나 | 상시. 대부분의 세트 |
| **B 패턴형** — 모티프 반복 | 시즌·기획전. 눈에 띄어야 할 때 |

### 1-5. MOQ가 부담되면 — 스탬프

인쇄 MOQ가 초기 물량에 비해 크면, **고무 스탬프 + 잉크패드로 직접 찍는 방법**이 있습니다.

| | 인쇄 | 스탬프 |
|---|---|---|
| 초기비 | 판비 + MOQ | **도장 제작비만** |
| 수량 | 많을수록 유리 | **적을수록 유리** |
| 톤 | 균일 | **찍을 때마다 미세하게 다르다** — 손그림과 궁합이 좋다 |
| 한계 | — | 물량이 늘면 사람 손이 못 따라간다 |

초기에 스탬프로 시작해 물량이 붙으면 인쇄로 옮기는 경로도 가능합니다.
**같은 원화를 쓰므로 옮길 때 디자인을 다시 만들 필요가 없습니다.**

## 2. 견적에서 받을 숫자

목형비가 빠졌으니 물어볼 것도 줄었습니다.

| 항목 | 메모 |
|---|---|
| **MOQ** | 이 결정의 유일한 큰 리스크. 안 팔리면 그대로 재고 |
| **인쇄판비** | 1도이므로 한 판 |
| **개당 단가** | 수량 구간별로 받는다 |
| 리드타임 | 재발주 주기 계산용 |
| 기성 규격표 | 고를 수 있는 사이즈 목록 |

> 숫자는 견적을 받아 이 표를 채웁니다. 지금 추정해 적지 않습니다.

## 3. 박스 위에 무엇이 올라가나

| 면 | 내용 | 원칙 |
|---|---|---|
| 뚜껑 상단 | 워드마크 · 모티프 | **여백을 크게.** 꽉 채우면 저가로 읽힌다 |
| 옆면 | 모티프 반복 또는 무지 | 반복 패턴은 1종만 |
| 안쪽 뚜껑 | **여는 순간 보이는 면** — 거북이 또는 한 줄 | 언박싱의 정점. `unboxing.md`에서 시퀀스 설계 |
| 바닥 외면 | 법정 표시 라벨 자리 | `label-spec.md` 7항목. **자리를 미리 비워 둔다** |

- 상황 이름(새 식탁·둘이 쓰는 상)은 **박스가 아니라 띠지**에 둡니다. 박스는 규격이 적고 오래 쓰는데,
  상황은 늘어나고 바뀝니다. **자주 바뀌는 정보는 자주 찍는 것에 올립니다.**
- 거북이는 한 박스에 **하나**입니다(`character.md` 규칙).

## 4. 강도 — 도자기가 들어간다

디자인 박스라도 먼저 물류 상자입니다.

- [ ] 골판지 종류·평량 확인 (단골·양면골 등). 도자기 세트 무게 기준
- [ ] **박스 안 고정 방식** — 습자지 구김만으로 버티는지, 인서트(칸막이)가 필요한지
- [ ] 낙하 테스트 1회 (실제 세트 무게로)
- [x] **택배 상자를 따로 씌운다 (2026-08-30 확정)** → 아래 §4-1

### 4-1. 2겹 구조 확정 — 겉 택배 상자 + 안 선물 박스

**선물 박스는 배송 상자가 아닙니다.** 겉에 택배 상자를 따로 씌웁니다.

| 층 | 무엇 | 역할 |
|---|---|---|
| 겉 | **무지 택배 상자** | 운송·완충·송장. 찍힘과 오염을 여기서 다 받는다 |
| 안 | **자체 디자인 선물 박스** | 브랜드. 받는 사람이 여는 것 |

**이 결정이 낳는 것**

| 좋아지는 것 | 감수하는 것 |
|---|---|
| 디자인 박스가 **깨끗한 상태로 도착**한다. 인쇄면에 송장·테이프를 안 붙인다 | 상자 하나 값 + 부피(택배 요율) |
| **완충을 겉에서 해결**할 수 있다 → 선물 박스 안은 습자지만으로 단정하게 유지 | 받는 사람이 두 번 연다 |
| **가격표 제거·별도 배송지 대응이 쉽다** — 겉만 바꾸면 된다 | 포장 공정이 한 단계 늘어난다 |
| 파손 시 겉 상자만 손상되는 경우가 많아 **클레임이 준다** | |

**따라오는 사양 결정**

- [ ] 겉 상자 규격 = 선물 박스 3종(S·M·L) + 완충 두께에 맞춰 **3종**. 목형 불필요(기성 규격 사용)
- [ ] 완충은 **겉 상자와 선물 박스 사이**에 넣는다(에어캡·종이 완충). 선물 박스 안은 습자지만
- [ ] **겉 상자에 브랜드를 드러낼지** — 무지가 기본. 받는 사람이 열기 전까지 선물인 걸 모르게 하는 편이
      언박싱이 산다. 다만 **테이프에 1도 인쇄**하는 건 저렴하고 효과가 크다(선택)
- [ ] 송장은 겉 상자에만. **선물 박스에는 어떤 배송 정보도 붙이지 않는다**
- [ ] 겉 상자를 열었을 때 **첫 화면** 설계 → `unboxing.md`

> 언박싱 시퀀스가 **두 단계**가 됩니다 — 택배 상자를 열면 선물 박스가 있고, 그걸 다시 엽니다.
> 두 번 여는 건 손해가 아니라 **선물의 문법**입니다. 포장을 뜯는 행위 자체가 선물이니까요.
> 다만 겉 상자 안이 휑하면 싸구려로 읽히니, `unboxing.md`에서 그 사이를 설계합니다.
