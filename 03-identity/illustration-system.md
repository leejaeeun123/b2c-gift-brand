# 일러스트 시스템

> **이 문서가 브랜드의 차별점 그 자체다.** 상품은 도매라 남과 겹치지만, 이 그림은 겹치지 않는다.
> 목표는 그림 한 장이 아니라 **누가 그려도 같은 손으로 보이게 하는 규칙**이다.

## 1. 정본은 "그린 것"이지 "생성한 것"이 아니다

**모티프 정본 = 재은이 만든 레퍼런스 시트를 그대로 벡터화한 것.**
코드로 형태를 만들지 않는다. 그림이 먼저 있고, 코드는 그걸 **따기만** 한다.

```
그림(PNG)  →  vectorize.py  →  motif-*.svg / char-*.svg
```

`vectorize.py`가 하는 일:

| 단계 | 내용 |
|---|---|
| 1 이진화 | 잉크/여백 분리 |
| 2 조각 묶기 | 떨어진 점·눈·잎을 한 모티프로 (팽창 후 연결요소) |
| 3 행 정렬 | 좌→우, 위→아래 순서로 이름 배정 |
| 4 **얼굴 이식** | 지정한 모티프의 얼굴을 다른 모티프 얼굴로 교체 (`FACE_SWAP`) |
| 5 **두께 정규화** | 모든 모티프의 *보이는* 획 두께를 하나로 맞춘다 (§2-1) |
| 6 윤곽선 추출 | `fill-rule="evenodd"` 단일 패스로 출력 |

- **형태는 바꾸지 않는다.** 손이 그은 선의 떨림·망설임·비대칭이 그대로 남는다
- 재현: `python vectorize.py [png경로]` · 두께는 `TARGET=4.6 python vectorize.py`로 조절

### 코드로 그리려다 실패한 기록

처음에 형태를 코드로 생성했다(`_deprecated/gen_motifs.py`). 규칙은 지켜졌지만 결과가 틀렸다.

| 시도 | 결과 |
|---|---|
| 얇은 선 + 잔떨림 | 손그림이 아니라 **깔끔한 벡터 아이콘** |
| 진폭을 키움 | 선이 자글거려 **노이즈** |
| 굵은 마커선으로 전환 | 톤은 가까워졌으나 **형태가 어색**(화병이 전구로, 접시가 눈알로) |

**교훈**: 손그림에서 코드가 만들 수 있는 건 떨림이지 **형태 감각**이 아니다. "왜 이 선이 여기 있는지"는 손이 정한다. 코드의 자리는 그 뒤, 따고 관리하는 일이다.

## 2. 스타일

### 2-1. 획 두께는 코드가 맞춘다 `TARGET = 4.6`

원본 시트는 모티프마다 두께가 달랐다. 원인은 두 가지였다.

1. 원본 자체의 두께 차이 — 하트만 유난히 굵게 그려져 있었다(19.6px vs 나머지 ~8px)
2. **크기 정규화의 부작용** — 각 모티프를 100×100에 맞춰 키우면 작은 그림일수록 선이 굵어 보인다

그래서 *소스 두께*가 아니라 **viewBox에서 보이는 두께**를 기준으로 맞춘다.
목표보다 가늘면 팽창, 굵으면 침식한다(하트가 여기 해당). 변형량은 최대 4px로 제한 — 그 이상 굵히면 내부 디테일이 서로 붙어 뭉갠다.

> 실측: TARGET 7.86(하트 원본 두께)로 맞추자 화병·책·배·포크가 **덩어리로 뭉갰다.** 4.6이 굵기와 디테일이 둘 다 사는 지점이다.

### 2-2. 얼굴은 한 가지만 쓴다

`FACE_SWAP = [("cup", "vase")]` — 잔의 얼굴을 화병 얼굴로 갈아 끼운다(원본 픽셀을 오려 눈 간격 비율로 확대 이식).
**얼굴이 둘이면 캐릭터가 둘로 읽힌다.** 얼굴 있는 사물은 전부 같은 얼굴을 쓴다.

### 2-3. 새 모티프가 지켜야 할 성격

| # | 특징 |
|---|---|
| 1 | **얇고 고른 선.** 붓펜이 아니라 가는 펜. 두께 변화가 거의 없다 |
| 2 | **모서리가 둥글다.** 각진 곳이 없고 전체가 부풀어 있다 |
| 3 | **삐뚤삐뚤하다.** 원이 정확한 원이 아니고, 좌우가 다르다 |
| 4 | **작은 얼굴을 넣기도 한다.** 점 눈 + 작은 입. 잔·화병·거북이·강아지에 있다 |
| 5 | **디테일은 무늬로.** 물결(볼 테두리), 점(거북이 등·배), 빗금(물고기 지느러미) |
| 6 | **면을 칠하지 않는다.** 하트만 예외적으로 굵게 |

## 2-4. 확장했을 때 같은 느낌이 나는가 — **코드가 보장하는 것과 아닌 것**

| 항목 | 누가 보장하나 |
|---|---|
| 획 두께 | ✅ **코드** — TARGET 4.6으로 자동 정규화 |
| 크기·여백 | ✅ **코드** — viewBox 92 안에 맞춰 중앙 정렬 |
| 색 | ✅ **코드** — `currentColor` 단색 |
| 얼굴 | ✅ **코드** — `FACE_SWAP`으로 통일 |
| 파일 형식·이름 | ✅ **코드** |
| **형태 감각** | ❌ **사람** — 비례, 생략 정도, 무엇을 그리고 무엇을 안 그릴지 |

즉 **두께가 들쭉날쭉하거나 크기가 안 맞는 문제는 다시 안 생긴다.** 코드가 매번 맞춘다.
반대로 "같은 손으로 그린 느낌"은 코드가 못 만든다. 그건 원본 시트를 만들 때 정해진다.

### 새 모티프 추가 절차

1. **기존 시트를 참조 이미지로 넣고** 같은 도구로 시트를 한 장 더 만든다
2. `python vectorize.py 새시트.png`
3. `NAMES` 배열에 순서대로 이름을 넣는다 (좌→우, 위→아래)
4. 얼굴 있는 사물이 새로 생기면 `FACE_SWAP`에 추가한다

**낱개로 만들지 말고 시트로 만든다.** 한 장에 같이 그려야 선의 성격이 유지되고, 두께 차이도 정규화가 감당할 범위 안에 들어온다.
원본 두께가 크게 다르면(3배 이상) 팽창·침식이 형태를 건드리므로, 그때는 시트를 다시 뽑는 게 낫다.

### 지금 없는 것 (다음 시트에서)
편지 · 선물 상자 · 트레이 · 주전자 · 냄비 — 상황 라벨 아이콘도 여기서 나온다.

## 3. 파일 사양

```
viewBox 0 0 100 100 · fill="currentColor" · fill-rule="evenodd" · stroke="none"
```

- **선이 아니라 면이다.** 윤곽을 따서 채운 형태라 `stroke-width`로 굵기를 바꿀 수 없다.
- 색은 부모의 `color`만 바꾸면 된다. 잉크/종이 양방향으로 쓴다.
- 크기를 키워도 깨지지 않지만, **아주 작게 쓰면 얇은 선이 사라진다.** 24px 이하에서는 별도 축소용이 필요하다(미제작).

## 4. 어디에 쓰나 / 어디에 안 쓰나

| ✅ 쓴다 | ❌ 안 쓴다 |
|---|---|
| 띠지 · 박스 · 스티커 · 완충지 | **제품 사진 위** |
| 메시지 카드 · 감사 카드 | 로고 대체 (로고는 워드마크) |
| 상황 라벨 아이콘 (진열·필터) | 배경 전면 패턴 (여백을 먹는다) |
| 상세페이지 구분선 · 스펙 아이콘 | 상품 썸네일 (상품이 안 보인다) |
| 인스타 단독 그래픽 · 에디토리얼 | 3개 이상 겹쳐 쌓기 |

**배치**: 한 화면에 **최대 2개**. 여백이 곧 가격대다(비주얼 원칙 3).

- **24px 이하 축소용 세트.** 얇은 선이라 파비콘·작은 아이콘에서 사라진다. 선을 굵힌 별도 버전이 필요하다.
- **없는 모티프 5종**(편지·선물 상자·트레이·주전자·냄비) 추가 시트.
